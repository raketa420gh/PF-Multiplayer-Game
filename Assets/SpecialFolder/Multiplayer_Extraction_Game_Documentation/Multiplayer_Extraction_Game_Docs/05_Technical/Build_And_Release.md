## Build Pipeline
- Content: generated by editor builders (DD-008).
- Dedicated server: `Tools/Game/Network/Build Dedicated Server` → `Builds/DedicatedServer/DungeonServer.exe` (StandaloneWindows64, all enabled scenes); logs per session next to it (`Tools/Game/Network/Open Server Logs`).
- Server launch (dev orchestrator `LocalServer`): `DungeonServer.exe -batchmode -nographics -dedicatedServer -session <name> -mode <QueueMode> -floor <n> -logFile <session>.log`. Release target: a real orchestrator allocating servers with the same arguments.
- The server build must match the client scenes and code: an older build gives Fusion "Behaviour count mismatch" on scene NetworkObjects. In the editor `LocalServer` detects a stale build and falls back to Host — rebuild the server after any scene/code change.

## Versioning
Один номер не решает несколько задач (DD-018). Четыре независимых идентификатора:

| Идентификатор | Отвечает на вопрос | Формат | Пример | Где живёт |
|---|---|---|---|---|
| Game Version | Что за версия игры | `MAJOR.MINOR.PATCH` | `0.7.0` | Player Settings → Version (`PlayerSettings.bundleVersion` = `Application.version`), git tag `v0.7.0` |
| Build | Какой именно бинарник | целое, только растёт | `1842` | генерируется при сборке (CI), не правится руками |
| Stage | На какой стадии продукт | `Pre-Alpha` / `Alpha` / `Beta` / `Early Access` / `Release Candidate` / `Release` | `Beta` | build info, Steam, Discord, patch notes |
| Steam branch | Кому предназначен бинарник | `default` / `playtest` / `experimental` / `internal` | `playtest` | Steamworks; у Steam свой Steam Build ID — игроку не показывается |

Стадия **не** зашивается в цифры: не `0.4 Alpha 3`, а `v0.4.0 — Alpha`.

### Правила номера версии
- `MINOR` — существенная новая функциональность (инвентарь, extraction, новый тип оружия, торговец, новая карта, новый этаж): `0.2.0 → 0.3.0`.
- `PATCH` — только исправления и баланс: `0.3.0 → 0.3.1 → 0.3.2`.
- `MAJOR` — новая эпоха продукта: `1.0.0` — когда игра считается полноценным релизом (а не когда «накопилось фич»); `2.0.0` — крупная несовместимость/перезапуск, не просто DLC.
- До `1.0.0` — `0.x.y`, в том числе весь Early Access (`0.10.0`, `0.11.0` допустимы).
- Пересборка без изменения версии — та же `Game Version`, новый `Build`: `v0.4.0 Build 1801 → 1802 → 1803`.
- Build растёт сквозь версии и никогда не сбрасывается: `v0.7.0 Build 1843 → v0.8.0 Build 1901`.
- SemVer pre-release / metadata (`0.7.0-beta.2+build.1842`) — только в CI и технических системах, не в брендинге.

### Ориентир версия ↔ стадия
| Версия | Стадия / фаза roadmap |
|---|---|
| `0.1.0` | Prototype |
| `0.2.0` | Core gameplay / Core Multiplayer Prototype |
| `0.3.0` | First playable / Vertical Slice |
| `0.4.0` | Closed Alpha |
| `0.5.0` | Open Alpha |
| `0.6.0`–`0.7.0` | Beta |
| `0.8.0` | Early Access |
| `0.9.0` | Release Candidate |
| `1.0.0` | Release |

Ориентир, а не закон: стадию меняет решение о стабильности, а не номер.

### Отображение
| Аудитория | Строка |
|---|---|
| Игрок (главное меню) | `v0.7.0`, ниже мелко `Build 1842` |
| QA / баг-репорты / логи | `v0.7.0 — Build 1842` (обязательно с Build) |
| Steam / Discord / patch notes | `Fantasy Extraction v0.7.0 — Beta` |
| Полная запись | `Fantasy Extraction v0.7.0 — Beta — Build 1842` |
| CI | `0.7.0+build.1842` или `0.7.0-beta.2+build.1842` |
| Git | tag `v0.7.0` на коммите релиза версии |

### Steam branches
| Branch | Назначение | Пример |
|---|---|---|
| `default` | Основная версия для игроков | `v0.4.0 Build 1837` |
| `playtest` | Публичное тестирование | `v0.5.0 Build 1861` |
| `experimental` | Нестабильные новые механики | `v0.6.0 Build 1874` |
| `internal` | Только команда | любой свежий Build |

### Поток
`git tag v0.7.0` → CI → Unity build (`Version = 0.7.0`, `Build = 1842`, `Stage = Beta`) → upload в Steam (Steam Build ID) → выставление на branch.

Клиент и dedicated server одной поставки собираются с одинаковыми `Game Version` и `Build`.

GDD-версии (`GDD v0.8` в `README.md` / `Changelog.md`) — версии документации, не игры.
