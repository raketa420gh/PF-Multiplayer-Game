# Combat Design

**Status:** Accepted for current prototype / GDD v0.3

## Reference
Основной референс по ощущению ближнего боя: **Dark and Darker**. Референс не является спецификацией; собственные правила проекта описаны ниже.

## Combat Pillars
1. **Физически читаемый бой** — направление взгляда, положение щита и траектория удара должны иметь непосредственное значение.
2. **Оружие определяет управление** — набор атак и защитных действий зависит от того, что находится в руках игрока.
3. **Риск через тайминг** — серии ударов, окна продолжения комбо и восстановление после блока создают моменты для принятия решений.

## Character Control / Body Model
- Персонаж — 3D гуманоид.
- Вид от первого лица.
- Камера находится на уровне глаз, в точке между глазами персонажа.
- При горизонтальном повороте мыши/камеры поворачивается весь гуманоид.
- При вертикальном взгляде корпус верхней части тела следует направлению взгляда, ноги остаются на месте.
- Диапазон вертикального взгляда: до **90° вверх** и **90° вниз**.
- При приседании нижняя часть тела/ноги выполняют приседание, верхняя часть тела сохраняет независимое управление направлением взгляда.
- Руки игрока видимы в first-person представлении.

## Input Model
Управление атакой/блоком определяется фактической конфигурацией рук.

| Конфигурация | Атака | Блок |
|---|---|---|
| Одноручное оружие в правой + щит в левой | ЛКМ | ПКМ |
| Двуручное оружие | ЛКМ | ПКМ |
| Одноручное оружие в левой | ПКМ | ЛКМ |

### Правило руки
- Одноручное оружие, помещённое в **правую руку**, использует основную атаку на **ЛКМ**.
- Одноручное оружие, помещённое в **левую руку**, использует основную атаку на **ПКМ**.
- Щит занимает противоположную руку и использует вторую кнопку мыши для блока относительно текущего оружия.
- Двуручное оружие занимает обе руки и использует ЛКМ для атаки и ПКМ для блока.
- Блок доступен не только щитом: **любое оружие может использоваться для блокирования**, если конкретное оружие допускает это по своей боевой конфигурации.

## Weapon Categories
- One-handed melee
- Two-handed melee
- Shield
- Ranged / two-handed ranged

Каждое оружие определяет:
- занимаемые руки;
- набор атак;
- длину и последовательность серии;
- окна продолжения серии;
- возможность блока;
- положение/ориентацию рук;
- набор атакующих и защитных анимаций;
- параметры импакта.

## Melee Attack Chains
- У каждого оружия ближнего боя есть собственная серия атак.
- Типичная длина серии: **2–3 удара**.
- После последней атаки серии следующий успешный ввод начинает серию заново с первой атаки.
- Следующая атака серии запускается только при попадании ввода в заданное **окно продолжения**.
- Окно продолжения находится ближе к концу текущего замаха.
- Нажатие вне окна не должно автоматически пропускать текущую атаку или произвольно менять последовательность; точное поведение при раннем вводе — **TBD**.

## Blocking
### General
- Блок можно выполнять оружием или щитом, если предмет поддерживает блок.
- У блока есть пространственное направление: результат зависит от взаимного угла между атакой и защитным предметом.

### Shield Angle / Partial Block
Полного бинарного «заблокировано / не заблокировано» недостаточно.

Пример:
- противник наносит вертикальный удар сверху вниз;
- игрок поднимает щит, но угол щита недостаточно точно перекрывает траекторию;
- оружие может одновременно коснуться щита и головы/другой уязвимой зоны;
- результатом становится частичная защита с потенциальным уроном по персонажу.

Следовательно, система должна учитывать как минимум:
- направление удара;
- ориентацию щита/оружия;
- точку пересечения;
- уязвимые зоны персонажа;
- степень перекрытия траектории.

Точная формула частичного блока — **TBD**.

### Block Impact
При ударе по щиту:
- возникает небольшой физический/анимационный импакт;
- щит временно теряет возможность блокировать;
- затем щит возвращается в исходное защитное положение.

Параметры, которые должны быть data-driven:
- block impact duration;
- block recovery duration;
- block angle tolerance;
- stamina cost, если будет использоваться;
- damage mitigation;
- stagger / hit reaction.

## Animation Requirements
Анимация атаки напрямую зависит от текущего оружия.

Необходимо поддержать:
- отдельные attack chains для каждого оружия;
- разные стартовые/финальные позы для правой и левой руки;
- переходы между idle → attack → recovery → combo;
- блок и возврат щита/оружия после block impact;
- first-person representation рук и оружия;
- синхронизацию first-person и third-person представления для сетевых игроков.
